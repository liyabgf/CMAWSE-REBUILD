# P6-D：typecheck 原生化决策报告

## 数据路径（引擎源码追踪）

agent_callable → 解析守卫（try/except 取键，batch/perm 两处）→ evaluate_d1/d4（.get 假定 dict，裸洞）/ d2（isinstance 局部守卫）/ d5（纯比较）→ 记录。typecheck 当前位置 = agent 包装层（P5）；原生化位置 = 内嵌 run_session 批次与置换调用层（P6 副本 rebuild/p6/native/，REWRITTEN，P3/P4/P5 零改动）。

## 原生化建议

- **A2 与 A3 在实测语料上结果完全等价**（崩溃 0、完整 24/24、零误拒、可追溯）。原生化（A3）的唯一增量价值：校验点进入引擎记录路径（pf 计数与默认值兜底语义同层）、对置换调用层同样覆盖、不依赖调用方记得包装。维护成本：A3 需维护引擎副本（已实测 v7 回归零破坏）；A2 需调用方纪律。
- **裁决：原生化可行且安全（A3 达标），但外挂已满足当前边界要求——不主张"必须"原生化。** 若未来引擎要对外提供接口或进入 Registry 归档，建议原生化为单层校验（一次维护点）；当前重建目的下保留 A2 外挂 + A3 副本存档。
- 结论范围：仅覆盖 24 用例语料；未对真实 LLM 输出分布外推。
